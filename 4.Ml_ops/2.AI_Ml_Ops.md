
## MLOps Notes

##  1. What is MLOPS

* MLOps means applying DevOps principles and practices to the ML lifecycle, including continuous integration, continuous training, deployment, and monitoring of ML models 
---

##  2. What are the phases of MLOPS
* **Data Management & Versioning**: Collect, validate, process, and version datasets and features (ETL).
* * **Development & Experimentation**: Develop ML code, experiment with different models and features, and track experiments.
* **Model Training**: Train models using versioned data and automate the training pipeline while tracking model artifacts and parameters.
* **Model Evaluation & Validation**: Evaluate model performance against defined metrics and thresholds before deployment.
* **Model Deployment / Serving**: Deploy the validated model for online or batch predictions and automate deployment using CI/CD.
* **Monitoring & Maintenance**: Monitor model performance, data/model drift, and infrastructure, and retrain the model when required.
---

## 3. MLOPS Pipeline steps 
* **Data Collection** → Collect data from databases, APIs, files, or other sources.
* **Data Validation & Preprocessing** → Validate data quality and clean/transform the data.
* **Data Versioning** → Version datasets and features to ensure reproducible training.
* **Development & CI** → Develop ML code and automatically test and validate code and pipelines.
* **Model Training** → Train the model using the prepared and versioned data.
* **Model Evaluation** → Evaluate the model against defined performance metrics and thresholds.
* **Model Registry** → Store and manage approved model versions and metadata.
* **Deployment/Serving** → Deploy the approved model for online or batch predictions using CD.
* **Monitoring** → Monitor model performance, data/model drift, and infrastructure.
* **Retraining** → Trigger a new training cycle when performance degrades or new data becomes available
---
## 4. What is RAG? 

* Retrieval-Augmented Generation (RAG) is used to improve the accuracy and relevance of an AI/ML model’s responses by providing it with external knowledge

    Retrieval: Getting relevant data from an external knowledge source.
    Augmentation: Adding the retrieved data as context to the prompt.
    Generation: Sending the augmented prompt to the LLM to generate a relevant response

* Common retrieval sources:

    Documents — PDF, DOCX, TXT
    Databases
    Vector databases
    Knowledge graphs
    APIs
    Web search
    Enterprise knowledge bases
---

## 5. What is fine-tuning 
* Retraining a pre-trained model on new, task-specific data to adapt it for a specialized task or behavior.

## Agent OPS Notes

## 1. Phases of Agent OPS

* Assessment / Discovery
   - Identify the business problem and use case
   - Define expected business outcome and success criteria
   - Determine whether an agent-based solution is required

* Architecture & Framework Selection
   - Choose framework/orchestration:
     ADK, LangGraph, etc.
   - Define agent architecture and workflow

* Model Selection
   - Select appropriate LLM/SLM based on:
     reasoning capability, accuracy, latency, cost, context window, and security
   - LLM → complex reasoning, planning, generation
   - SLM → classification, extraction, routing, repetitive tasks

* Development
   - Define agent instructions/system prompts
   - Configure tools and tool permissions
   - Implement workflows/orchestration
   - Configure memory/state and external integrations

* Guardrails & Security
   - Authentication & authorization
   - Prompt-injection protection
   - Input/output validation
   - PII/data protection
   - Content and safety controls
   - Tool access restrictions

* Evaluation & Testing
   - Functional testing
   - Agent/tool-call evaluation
   - Accuracy and hallucination testing
   - Safety and security testing
   - Performance, latency, and cost evaluation

* Deployment
   - CI/CD
   - Versioning
   - Secrets/configuration management
   - Scalability and rollback strategy

* Monitoring & Observability
   - Agent traces and tool calls
   - Latency and errors
   - Token usage and cost
   - Quality/evaluation metrics
   - Security events
   - Continuous evaluation and improvement

## 6. Explain MCP, A2A protocol 
* **MCP** is a standard protocol that defines how  Agents can access/connects to external tools, data sources, API's 
* **A2A** is a standard protocol that defines how  Agents can communicate/collaborate with other Agents for task distribution, context sharing, response sharing, and Agent discovery 
---
## 7. Agent Workflows 
* **Sequential**: Agents execute one after another, where the output of one agent may become the input/context for the next agent. Typically used for dependent tasks.
* **Parallel**: Multiple agents execute simultaneously, typically performing independent or loosely coupled tasks, and their results can be combined afterward.
* **Loop**: An agent or group of agents repeatedly executes a task until a specific condition is met or a maximum iteration limit is reached. Typically used for iterative refinement, validation, and error correction.
---
## Agent trajectory 
* Agent trajectory is the sequence of actions, tool calls, and intermediate steps an agent takes while completing a task.
