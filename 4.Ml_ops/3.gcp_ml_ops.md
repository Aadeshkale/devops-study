# Agent Platform

## MLOPS

### Pipeline 
* Pipeline automates and orchestrates the end-to-end ML workflow by connecting multiple stages such as data preparation, training, evaluation, and deployment
* In GCP Agent Platform Pipelines, pipelines can be defined using **Kubeflow** Pipelines (KFP) or **TensorFlow** Extended (TFX).
---
### Model Registry 
* Model Registry is used to register, manage, version, and track trained ML models. It does not primarily store the model files itself.
* The actual model artifacts are stored in an artifact location such as:
   * Cloud Storage (GCS) → model files/artifacts
   * Artifact Registry → container images used for custom model serving/training
---

### Deployment & Serving

* Makes a trained model available for inference/predictions.
    * **Online Prediction / Online Inference** → Uses a managed **Endpoint** to provide real-time, low-latency predictions or generations.
    * **Batch Prediction / Batch Inference** → Uses a **Batch Prediction Job** to process a large dataset asynchronously. Results are available after the job completes; an online **Endpoint is not required**.

---   
### Dataset 
* Dataset is a managed ML data resource used to organize, manage, version, and provide data for ML training and evaluation.
* Supported data sources depend on dataset type:
    * BigQuery → Tables/views
    * Cloud Storage → CSV, JSONL, images, etc.
    * DataFrames → Supported for certain multimodal workflows
    * Versioning → Helps track different dataset versions and identify which dataset/version was used for training.
    * Lineage → Helps track the relationship between datasets and ML workflows.
---
### ML Metadata: 
* ML Metadata (MLMD) is used to track, store, and manage metadata about ML workflows ( workflow means pipeline + stages )
* Basically, it tracks the metadata of each pipeline step / ML stage and the relationships between them. 
    * Data versioning → which dataset/version was used.
    * Model versioning → which model/version was created.
    * Input / Output artifacts → datasets, models, checkpoints, etc.
    * Parameters → hyperparameters/configuration used during execution.
    * Evaluation results → accuracy, precision, recall, loss, etc.
    * Execution details → pipeline/stage execution and status.
    * Lineage → relationship between data → training → model → evaluation.
---
### Monitoring:
* Monitoring → Monitors the health, performance, and behavior of deployed ML models and infrastructure.
    * Cloud Monitoring → Metrics, resource utilization, latency, requests, errors, dashboards, and alerts.
    * Cloud Logging → Logs from applications, endpoints, and infrastructure.
    * Agent Platform Model Monitoring → Detects model/data issues such as feature drift and prediction/input distribution changes.
    * Cloud Trace → Helps analyze request latency and distributed application performance.
---

## Agent OPS 


### Agent Development 
* Agents can be developed using ADK and other supported frameworks such as LangChain, LangGraph, AG2, and LlamaIndex.
* Custom agent frameworks are also supported.

### Agent Runtime 
* Agent Runtime is a fully managed Google Cloud runtime used to deploy, operate, and scale AI agents.
* Supports agents built with ADK and supported frameworks
* Custom agents can be deployed using a Dockerfile or custom container image from Artifact Registry
* Deployments are done through the **Agent Platform SDK**

### Agent Identity 

* Agent Identity provides a unique, per-agent identity for AI agents running on Google Cloud. It is SPIFFE-based and tied to the agent's lifecycle.
* It is used to authenticate and authorize an agent when accessing:
    Google Cloud resources
    MCP servers
    APIs/tools
    Other agents
* IAM can be used to grant or deny permissions to the agent identity, enabling a least-privilege model.

### Agent Gateway 
* Used to control where your agents can communicate, i.e other agents, MCP servers, tools, API's  
* Uses **Agent Identity** to identify agents and support authentication and authorization.
* Helps enforce security and access policies for agent-to-agent and agent-to-tool communication.  
* It makes use of **Model Armor** 


### Model Armor:
* Model Armor is a Google Cloud security service for protecting generative AI applications, LLMs, and AI agents. 
* It scans user prompts and model responses for security and safety risks such as prompt injection, jailbreak attempts, malicious URLs, sensitive data leakage, and harmful content
